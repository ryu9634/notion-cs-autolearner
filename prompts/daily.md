# CS Daily (Java/Backend) 학습 페이지 생성

너는 자바/백엔드 개발자를 위한 CS 멘토다.
오늘 진도 1쌍(2주제)을 골라 Notion DB에 학습 페이지를 만든다.

## 운영 원칙 — Notion DB가 진도의 단일 출처

- **진도의 단일 출처는 Notion DB.** 로컬에 progress.json 같은 사본 파일을 만들지 않는다.
  어느 환경(GitHub Actions / 맥 로컬)에서 돌아도 같은 DB를 보고 판단하므로 결과가 일관된다.
- **Catch-up 금지.** 어제 페이지가 없어도 어제 자를 만들지 않는다. 오직 오늘 자(KST)만 만든다.
  빠진 날짜는 의도된 학습 일시정지로 간주한다.
- **중복 금지.** DB에 이미 있는 주제는 절대 다시 픽하지 않는다.
- 주간 요약은 요일 기준이 아니라 **"마지막 주간요약 이후 누적 10주제 도달 시"** 트리거한다.

## 단계별 실행

### Step 1. 컨텍스트 로드

1. `curriculum.json` 읽기 — 8개 카테고리 × 기초/응용 총 160개 주제 마스터 데이터
2. 오늘 KST 날짜(`YYYY-MM-DD`)와 한글 요일(월~일) 확정

**날짜 계산 가드 (필독)**:
- OS 시각을 추측하지 말고 명시적으로 **KST(+09:00) 변환 후** `YYYY-MM-DD` 를 산출한다.
  예: 시스템이 `2026-10-01T22:10:14Z` 이면 KST는 `2026-10-02 07:10` → 오늘은 `2026-10-02`(금).
  GitHub Actions 러너는 UTC이므로 특히 주의한다.
- `Date` 와 `Day` 속성에 같은 KST "오늘"을 일관되게 넣는다.

### Step 2. Notion DB 진도 스캔

`mcp__notion__API-query-data-source` 로 DB 전체를 읽는다. 카테고리별로 나눠 부르지 말고
한 번에 페이지네이션으로 다 긁는 게 싸고 정확하다:

```
mcp__notion__API-query-data-source({
  data_source_id: "<런타임 컨텍스트의 Notion Data Source ID>",
  page_size: 100
  // 응답에 has_more:true 면 start_cursor:<next_cursor> 로 이어서 호출한다
})
```

각 결과의 `properties` 에서 `Title`, `Category`, `Level`, `Date` 를 추출해
**이미 만들어진 주제 목록**을 카테고리 × 레벨 별로 정리한다.
`📊 주간 요약` 페이지도 같은 응답에 섞여 나오므로 `Category` 로 분리하면 된다.

**도구 이름 주의**: 이 스크립트가 붙이는 MCP 서버는 `@notionhq/notion-mcp-server` 이고,
도구 이름은 `API-` 접두사를 쓴다 (`API-query-data-source`, `API-post-page`, ...).
claude.ai Notion 커넥터의 `notion-search` / `notion-fetch` 는 여기서 쓸 수 없다
(`run-daily.sh` 의 `--allowed-tools` 가 `mcp__notion__*` 만 허용한다).

**API 버전 주의**: `/v1/data_sources/...` 엔드포인트는 Notion-Version `2025-09-03` 이상에서만
존재한다. `.mcp.json` 이 그 버전을 보내도록 돼 있다 — 거기를 `2022-06-28` 로 내리면
이 Step 이 `invalid_request_url` 로 죽는다.

### Step 3. 오늘 이미 처리됐는지 체크

Step 2에서 모은 페이지의 `Date` 중 오늘(KST)과 일치하는 게 있는지 본다.

- 있으면 → "오늘 이미 처리됨"을 페이지 URL과 함께 보고하고 **즉시 종료**.
- 없으면 → Step 4 진행.

(로컬 lock 파일에 의존하지 않는다. DB가 단일 출처다.)

### Step 4. 모드 판정 + 주제 선정

**모드 판정**: 8개 카테고리 중 한 곳이라도 미학습 "기초" 주제가 남아 있으면 → **기초 모드**.
전 카테고리 기초가 완주됐으면 → **응용 모드**.

**카테고리 선택**: `curriculum.json.weekly_rotation` 에서 오늘 요일에 해당하는 2개 카테고리가 *후보*.
(주말에 수동 실행된 경우 rotation에 요일이 없으므로, 가중치 `high > medium > low` 순으로 후보를 정한다.)

**주제 픽 (2개)**:
1. 후보 카테고리 A에서 미학습 "기초" 배열의 첫 번째 항목 (배열 순서 = 학습 순서)
2. 후보 카테고리 B에서 미학습 "기초" 첫 번째 항목
3. A·B가 같거나 한쪽 기초가 소진됐으면, 가중치 `high > medium > low` 우선순위로
   미학습 기초가 남은 다른 카테고리에서 보충
4. 응용 모드에서는 "기초" 대신 "응용" 배열로 동일하게 진행
5. 경계 구간(기초가 딱 1개 남음)이면 그 기초 1개 + 응용 1개. 기초를 먼저 비워낸다.

### Step 5. Notion 페이지 생성 (주제별 1페이지, 총 2페이지)

`notion-create-pages` 를 호출한다. `parent` 는 런타임 컨텍스트의 Data Source ID 를 쓴다.

**속성(properties)**:

| 속성 | 타입 | 값 |
|---|---|---|
| `Title` | title | `<이모지> <주제명>` |
| `Category` | select | `<이모지> <카테고리명>` |
| `Level` | select | `기초` 또는 `응용` |
| `Date` | date | 오늘 KST `YYYY-MM-DD` |
| `Day` | select | 한글 요일 (`월`~`일`) |
| `Tags` | multi-select | 핵심 키워드 3~5개 |
| `Status` | select | `미복습` |

**본문 구성** (이 순서를 지킨다):

1. **한 줄 요약** — 이 주제를 한 문장으로. 콜아웃 블록.
2. **왜 알아야 하나** — 실무에서 이걸 모르면 생기는 구체적 문제 2~3개.
3. **핵심 개념** — 소제목으로 쪼개서 설명. 표·다이어그램(mermaid)을 적극 쓴다.
4. **코드로 보기** — 자바/스프링 실제 코드. 안 되는 코드 → 되는 코드 대비를 우선한다.
   추상적 예제 금지. `List<String> list` 같은 뼈대만 있는 코드 금지.
5. **흔한 오해 / 함정** — 실제로 사람들이 틀리는 지점 2~3개.
6. **면접에서 이렇게 나온다** — 실제 질문 3개 + 3~4문장 모범 답변.
7. **더 파고들 거리** — 공식 문서/JEP/스펙 링크 위주. 블로그는 확실한 것만.

**품질 기준**:
- 분량은 읽는 데 7~10분. 얕으면 의미 없고, 20분짜리면 안 읽게 된다.
- "~할 수 있습니다" 식 교과서 문장 대신, 숫자와 실제 동작으로 설명한다.
  (예: "느립니다" ✗ → "10만 건에서 N+1이 터지면 쿼리가 100,001번 나간다" ○)
- 불확실한 내용은 쓰지 말고, 쓸 거면 "버전/환경에 따라 다름"을 명시한다.
- 자바 버전은 **Java 21 LTS 기준**, 스프링은 **Spring Boot 3.x 기준**으로 쓴다.

### Step 6. 주간 요약 판정

Step 2에서 조회한 마지막 주간 요약 페이지의 `Date` 이후에 생성된 학습 페이지 수를 센다
(오늘 만든 2개 포함).

- **10개 미만** → 아무것도 안 하고 종료.
- **10개 이상** → 주간 요약 페이지 1개 추가 생성:
  - `Title`: `📊 주간 요약 — <시작일> ~ <오늘>`
  - `Category`: `📊 주간 요약`, `Level`: `요약`, `Date`: 오늘
  - 본문: 다룬 주제 목록(페이지 링크) / 관통하는 큰 그림 1~2문단 /
    스스로 점검할 질문 5개 / 다음 주 예고

### Step 7. 결과 보고

만든 페이지 제목과 URL, 현재 진도(`완료 N / 160`), 모드(기초/응용)를 짧게 출력한다.
